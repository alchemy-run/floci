    AWS IoT SiteWise

    Protocol: REST JSON Endpoint: http://localhost:4566/, signed for iotsitewise (the api., data. and monitor. hosts alike).

    Floci runs IoT SiteWise's asset modeling, its data plane with computed transforms and metrics, SiteWise SQL, gateways, SiteWise Monitor, bulk imports and storage settings, and the newer workspace, dataset, computation model and assistant APIs.

    Asset models and assets

    Asset models are CREATING, then ACTIVE; an update makes a model UPDATING until its assets carry the new definition, and a delete makes it DELETING until it's gone, each for floci.services.iotsitewise.transition-millis (1000). A model refuses changes while it isn't ACTIVE (ConflictingOperationException). Each update is a new version: assetModelVersion reads LATEST or ACTIVE, and If-Match/If-None-Match compare against the version's ETag (PreconditionFailedException).

    Definitions are checked as SiteWise checks them: unique property and hierarchy names, the data types each property type allows (transforms and metrics output DOUBLE or STRING), attribute defaults of the property's type, expressions that parse, variables that name properties of the model (or, for metrics, of a hierarchy's child model), no aggregation in transforms, metrics that read only metrics with the same window, and no property that depends on itself. Variables written with a property's name are stored with its ID.

    Composite models can be inline, created on their own and nested, or composed from component models (composedAssetModelId); interfaces are implemented with PutAssetModelInterfaceRelationship, matching properties by name, by override or by creating them.

    Assets carry their model's property, hierarchy and composite model IDs. Each property's alias, notification state and unit are set on the asset and survive model updates. Assets associate to a parent through a hierarchy of the parent's model, and one with a parent or children can't be deleted. A model with assets can't be deleted.

    Data

    BatchPutAssetPropertyValue takes values named by asset and property ID or by alias. Each value's type must match the property's, its time stamp must be within 7 days in the past and 10 minutes in the future (TimestampOutOfRangeException), and transforms and metrics can't take values. Values sent to an alias no asset property has go to a disassociated data stream, created with the data type of its first values unless the storage configuration disables disassociated storage. AssociateTimeSeriesToAssetProperty moves a stream and its history to a property; DisassociateTimeSeriesFromAssetProperty moves them back.

    Transforms run whenever one of their inputs gets a value, at that value's time, with each variable's latest GOOD value. Metrics run on each tumbling window once it ends, every floci.services.iotsitewise.metric-tick-millis (1000), with the window's start exclusive and its end inclusive, and place their value at the window's end; late data in a window already computed computes it again. Hierarchy variables read every child asset's property. The formula language has SiteWise's operators, constants and functions: common math, comparison, conditional (if, elif), string (len, find, contains, upper, lower, jp, join, format, f-strings, indexing and slicing), date and time (now, timestamp, mktime, localtime and its parts), aggregation and temporal functions in metrics, and pretrigger in transforms.

    A property with notifications ENABLED publishes a PropertyValueUpdate message for each value it gets on its $aws/sitewise/asset-models/<model>/assets/<asset>/properties/<property> topic, on Floci's AWS IoT broker.

    The data plane reads the latest value, history (ascending or descending, filtered by quality), aggregates over 1m, 15m, 1h and 1d windows (AVERAGE, COUNT, MAXIMUM, MINIMUM, SUM, STANDARD_DEVIATION) and linear or LOCF interpolation, each also in batch.

    SiteWise SQL

    ExecuteQuery runs on floci-duck over the views asset, asset_property, raw_time_series, latest_value_time_series and precomputed_aggregates. Views listed with commas in a FROM clause are joined on asset_id and property_id, as SiteWise joins them. STR_REPLACE, DATE_ADD, DATE_SUB, TIMESTAMP_ADD, TIMESTAMP_SUB, TO_TIMESTAMP, TO_DATE, TO_TIME, SUBSTR with a pattern, CAST ... FORMAT, STDDEV and NOW are rewritten for DuckDB. Results page through nextToken. Floci starts floci-duck in the background once SiteWise resources are created (floci.services.iotsitewise.prestart-query-engine), so the first query doesn't wait for it.

    Gateways and SiteWise Monitor

    Gateways run on Greengrass V2 (version 2 or 3), Greengrass V1 or Siemens Industrial Edge, at most one on each core device or thing. A capability configuration is OUT_OF_SYNC from the moment it changes, since no gateway reports back.

    Portals need an existing IAM role and are CREATING, then ACTIVE. A portal's start URL is served by Floci at /_floci/iotsitewise/portals/<id>, listing its projects, their dashboards and the assets they share, and its PNG logo at the image location's URL. Dashboards' definitions are JSON with a widgets list whose metrics name existing assets and properties. Access policies grant IAM Identity Center users and groups on SSO portals and IAM users and roles on IAM portals. A portal with projects, or a project with dashboards, can't be deleted.

    Bulk imports and storage

    Bulk import jobs read CSV files with the columns they name, Parquet files (through floci-duck), MP4 clips into VIDEO streams and annotation files into ANNOTATION streams. A job is PENDING, RUNNING, then COMPLETED, COMPLETED_WITH_FAILURES with each rejected row in errors.csv under the error report location, or FAILED. With adaptive ingestion, rows from the last 30 days run computations and notifications.

    PutStorageConfiguration sets the retention period, disassociated data storage, refusing null and NaN values, and the cold tier: MULTI_LAYER_STORAGE with a customer managed S3 location, to which Floci replicates time series under raw/, their one-minute aggregates under agg/ (Avro with Snappy, SiteWise's schemas and paths), index files, and asset and hierarchy metadata as NDJSON, once when it's configured and then every floci.services.iotsitewise.cold-tier-export-seconds (21600). Default encryption takes a KMS key that exists. Logging at ERROR or INFO writes rejected ingestion to the /aws/iotsitewise log group.

    Computation models and actions

    Anomaly detection computation models bind input and result properties of an asset model or of assets. The AWS/ANOMALY_DETECTION_TRAINING action resamples the inputs at the target sampling rate over the training range and learns each input's mean and spread (training fails with fewer than floci.services.iotsitewise.min-training-samples (10) samples). AWS/ANOMALY_DETECTION_INFERENCE then runs at the data upload frequency, scoring each sample by how far its inputs are from training and writing a JSON result to the result property (prediction, prediction_reason, anomaly_score and per-input diagnostics). The Training, Inference and TrainingWithInference actions of an asset's AWS/L4E_ANOMALY composite model run the same way on the properties its AWS/L4E_ANOMALY_INPUT attribute lists. Every action is an execution, listed and described with its result.

    Workspaces

    Workspaces hold applications, container tasks, pipelines, queries, searches, datasets and jobs. A pipeline execution runs each compute node as a Docker container of its task's image, with the pipeline's, task's, node's and execution's environment variables, once the nodes it depends on succeed; a node that exits non-zero fails the execution and the nodes after it. Workspace queries run SiteWise SQL asynchronously. Searches score time series in datasets by the words of the statement their aliases and names hold, and find each one's highest value. Event detection enrichment marks a dataset's segments in its range enriched; dataset exports write each time series as CSV under the destination; and GetCaptureData returns a VIDEO stream's clips.

    InvokeAssistant converses with a Bedrock model through Floci's Bedrock Runtime (floci.services.iotsitewise.assistant-model-id), with the Region's assets as context and SiteWise SQL as a tool, and streams its answer as an output event.

    Configuration

    floci:
  services:
    iotsitewise:
      enabled: true
      transition-millis: 1000
      metric-tick-millis: 1000
      cold-tier-export-seconds: 21600
      max-asset-models: 1000
      max-assets: 100000
      max-properties-per-model: 1000
      max-active-bulk-import-jobs: 10
      min-training-samples: 10
      assistant-model-id: anthropic.claude-3-5-sonnet-20240620-v1:0
      prestart-query-engine: true
