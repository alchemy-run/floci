# Amazon S3 Control

**Protocol:** REST XML, signed with `s3`
**Endpoint:** `http://localhost:4566/v20180820/...`, with the account in the `x-amz-account-id` header

S3 Control manages the account-level parts of Amazon S3: access points, Object Lambda access points, Multi-Region Access Points, S3 Storage Lens, S3 Batch Operations jobs, and S3 Access Grants. Requests and responses follow the botocore model vendored in `src/main/resources/aws/s3control-rest-xml.json` (regenerated by `tools/aws/regen_rest_xml_shapes.py`).

## The account header

Every request names its account in `x-amz-account-id`, and the header must be the caller's own account; another account is `AccessDenied` (403). The configured default (management) account may act on any account, because Lambdas Floci launches resolve to that account. Resources are stored per calling account and per signing Region, except Multi-Region Access Points, which belong to the account alone.

## Access points

`CreateAccessPoint` needs an existing bucket and a name of 3 to 50 lowercase letters, digits and hyphens. A second access point of the same name is `AccessPointAlreadyOwnedByYou` (409). An access point has an alias, a `NetworkOrigin` of `Internet` (or `VPC` with a `VpcConfiguration`), and a Block Public Access configuration whose flags default to on. Policies must be JSON with a `Statement`. `GetAccessPointPolicyStatus` reports a policy as public when an `Allow` statement grants `*` without a condition. Scopes hold the prefixes and permissions an access point is limited to. A bucket ARN, an access point ARN and the other resource ARNs below can be tagged through `/v20180820/tags/{arn}`.

## Object Lambda access points

An Object Lambda access point needs a supporting access point that exists in the same account and Region, and each transformation names a Lambda function. An access point that supports one can't be deleted until the Object Lambda access point is.

## Multi-Region Access Points

`CreateMultiRegionAccessPoint`, `DeleteMultiRegionAccessPoint` and `PutMultiRegionAccessPointPolicy` are asynchronous, as on AWS: each returns a request token ARN in us-west-2 that `DescribeMultiRegionAccessPointOperation` reports on. Creating takes a second: the request is `INPROGRESS` and the access point `CREATING`, then `SUCCEEDED` and `READY`. A Multi-Region Access Point takes one existing bucket per Region, 1 to 17 of them. Its routes start with every bucket at 100%, and `SubmitMultiRegionAccessPointRoutes` changes their traffic dials.

## Storage Lens

A Storage Lens configuration needs an `Id` that matches the route, `AccountLevel` and `IsEnabled`, and can't have both `Include` and `Exclude`. Storage Lens groups take a filter of prefixes, suffixes, tags, object ages or sizes (or `And`/`Or` of them); ranges are checked to be ordered. Floci stores both and returns them; it computes no metrics.

## Batch Operations jobs

`CreateJob` checks that the role exists in IAM, that the job has exactly one operation, one of `Manifest` and `ManifestGenerator`, a priority, and a `Bucket` and `ReportScope` when the report is enabled. `ClientRequestToken` makes the call idempotent. The manifest is read when the job is created:

- A CSV manifest (`S3BatchOperations_CSV_20180820`) lists bucket, URL-encoded key and optional version per line, in the order its `Fields` give.
- An S3 Inventory manifest (`S3InventoryReport_CSV_20161130`) names the inventory's CSV files.
- A manifest generator lists the source bucket, filtered by key prefix, suffix and substring, creation time, size and storage class, and can write the generated manifest.

A manifest that can't be read fails the job with `ManifestReadFailure`. A job with `ConfirmationRequired` waits in `Suspended` (`AWAITING_CONFIRMATION`) until `UpdateJobStatus` makes it `Ready`; any other job runs when it is created. Running applies the operation to every object: `S3PutObjectTagging`, `S3DeleteObjectTagging`, `S3PutObjectCopy`, `S3PutObjectAcl`, `S3InitiateRestoreObject`, `S3PutObjectLegalHold`, `S3PutObjectRetention`, `S3ComputeObjectChecksum`, or `LambdaInvoke` with the S3 Batch Operations event. The job then ends `Complete`, or `Failed` with `AllTasksFailed` when every task failed, with its progress summary and, when enabled, a CSV completion report and `manifest.json` under `<prefix>/job-<id>/`. A job that hasn't finished can be `Cancelled` and have its priority changed; any other transition is `InvalidRequest` with "job status forbidden".

## Access Grants

An account has one Access Grants instance per Region, optionally associated with an IAM Identity Center instance. Locations register `s3://` (the `default` location) or an `s3://bucket/prefix` scope with the IAM role that vends access to it. Grants give `READ`, `WRITE` or `READWRITE` on a location's sub-prefix (or one object, with `S3PrefixType` `Object`) to an IAM principal, or to an Identity Center user or group when the instance has Identity Center. A location with grants, or an instance with locations, can't be deleted.

`GetDataAccess` finds the caller's narrowest grant that covers the target with the requested permission, matching an IAM grantee against the caller's user or role session ARN, the role behind it, and the account root. It returns temporary credentials for the location's role, limited by a session policy to the grant's scope (or to the target alone with `Privilege=Minimal`), and registers them with IAM, so they sign S3 requests. A caller with no such grant gets `AccessDenied`. `ListCallerAccessGrants` lists the caller's grants.

## Not available

S3 on Outposts buckets (`CreateBucket`, `GetBucket`, and the bucket lifecycle, policy, replication, tagging and versioning operations of S3 Control) need an Outpost, and Floci has none: they answer `NoSuchOutpost` (404). `ListRegionalBuckets` without an Outpost is an empty list. Access points for directory buckets list the access points of buckets named `--x-s3`.

## IAM enforcement

With IAM enforcement on, each route is checked as the `s3:` action of its operation, against the resource the route names: an access point, an Object Lambda access point (`s3-object-lambda`), a Multi-Region Access Point (no Region), a Storage Lens configuration or group, a job, or an Access Grants instance, location or grant. Create and list routes are checked against `*`. The account-level Block Public Access and the tagging routes are described in [S3](s3.md#iam-enforcement-of-s3-control).

## Configuration

S3 Control is part of S3 and follows `FLOCI_SERVICES_S3_ENABLED`.

For the upstream API shape, see the [Amazon S3 Control API Reference](https://docs.aws.amazon.com/AmazonS3/latest/API/API_Operations_AWS_S3_Control.html).
